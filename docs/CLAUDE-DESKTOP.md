# Install or update the local development build

Use the two matching packages together on Windows x64 with Capella 7.1.0. Close out pending jobs and reconcile any uncertain outcome before changing versions. Keep the existing connection state directory and journal.

1. At a time of your choosing, finish your work in Capella, decide which changes to save, and stop the connector using **Independent MCP → Start / Stop Independent MCP (Development)**.
2. In **Help → Install New Software → Add → Archive**, select `capella-mcp-update-site-0.7.1-capella-7.1.0.zip`. Select the Independent Capella MCP development feature, review the update and complete the requested restart.
3. In Claude Desktop open **Settings → Extensions → Advanced settings → Install Extension** and select `independent-capella-local-0.9.1-win-x64.mcpb`. Replace the earlier extension, then fully quit and reopen Claude after finishing active tasks. This makes each Chat, Cowork and Code process use the same tool contract. The extension includes portable Python. The development packages are unsigned.
4. Ask Claude to call `capella_connection`. In a disposable open model, select one **architecture root**, a **logical component**, or **System Engineering** in the semantic tree. Run **Start / Stop Independent MCP (Development)**, check the scope in the dialog and select the reported `connection.json` file. An architecture root authorizes that architecture's containment subtree. A logical component authorizes its subtree and the architecture's single root logical function tree. System Engineering explicitly authorizes the selected model subtree across its layers, including cross-layer trace endpoints.
5. Ask Claude to list the paired diagrams and the owner and reference of a named element. For an incremental edit, identify the intended parent or endpoints by reference and ask Claude to prepare the smallest plan. To add a function to a component, create the function under its functional parent, then allocate it to the component. To change a diagram, select the descriptor reference and issue a separate `show_element` operation.
6. Review the preview. Submit with its exact digest and one request identity. Poll until terminal. On `succeeded_unsaved`, inspect the model and choose whether to save. Run the same menu command to stop pairing.

The local connector reads its selected profile on each poll. Different Claude conversations share the paired model, revision and permissions. To pair a different session, stop the old connector and restart all local extension processes before manual activation. Broker restart requires a fresh native publication. A stale preview requires a new snapshot and preview. An executing or unknown job can be reconciled by its matching receipt. Inspect the model and job after an interruption. Reusing a new request ID to force the same edit risks duplicating it.

For troubleshooting, first check the native bundle and extension versions, manual selection, enabled Capella viewpoint and the result of `capella_connection`. If a representation is unloaded, open it manually in the paired session, then query again. If a filtered query is empty, inspect the publication limits and try a narrower pairing. A diagram and its visible endpoint views must match the requested operation. Consult [the matrix](CAPABILITIES.md).

New diagrams appear in the paired inventory. Open them yourself in Capella after the job reports success, and arrange them there if needed. For acceptance tests, check the job and confirm the representation in a fresh snapshot before opening its editor.

Windows state lives in the current user's local application data under `IndependentCapellaMCP`. It contains a credential and journal. Model summaries requested through MCP enter the Claude conversation. The stdio command for a client configured manually is the extracted `runtime/python.exe` with `-I -B` and the absolute path to `server/local_stdio.py`. Use a fresh explicit `--state-dir` for any isolated test. The normal local route needs no hosting, URL or OAuth setup.
